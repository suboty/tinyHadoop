## 1. Запуск служб Hadoop — HDFS и YARN

Чтобы начать использовать службу Hadoop, мы должны запустить демоны службы Hadoop. Мы делаем это как пользователь «hadoop» из нашей среды Linux.

1.1. Откройте терминал, выбрав значок терминала в нижней левой панели или щелкнув правой кнопкой мыши в любом месте рабочего стола.

1.2. Измените пользователя на «hadoop» с помощью команды su. Пароль «hadoop».

```
su - hadoop
```

1.3. Измените рабочий каталог на ~/hadoop/sbin и выполните сценарий start-dfs.sh, чтобы запустить службы HDFS.

```
cd ~/hadoop/sbin
./start-dfs.sh
```

Вы получите вывод, аналогичный приведенному ниже.

```
[hadoop@localhost sbin]$ ./start-dfs.sh
Starting namenodes on [localhost]
Starting datanodes
Starting secondary namenodes [localhost.localdomain]
```

Вы успешно запустили демон namenode и datanode для служб HDFS.

1.4. Выполните сценарий start-yarn.sh, чтобы запустить службы YARN.

```
./start-yarn.sh
```

1.5. Вы получите вывод, аналогичный приведенному ниже.

Вы успешно запустили демон resourcemanager и nodemanagers для сервисов YARN.

1.6. Убедитесь, что все демоны запущены, с помощью утилиты jps. Она показывает список запущенных Java-процессов.

```
jps
```

Вы должны увидеть следующие процессы:

```
NameNode
DataNode
SecondaryNameNode
ResourceManager
NodeManager
```

Если какого-то из процессов нет — служба не запустилась, следует проверить логи в каталоге `~/hadoop/logs`.

1.7. Теперь вы можете выйти из сеанса как пользователь Hadoop.

Сделайте это, введя exit в терминале.

Если ОС Linux будет выключена в какой-то момент времени, вам придется повторить описанные выше шаги, чтобы запустить службы HDFS и YARN. Во избежание этого, не следует выключать виртуальные машины. По завершении лабораторной работы выйдите из виртуальной машины, используя меню «File» («Файл») > «Close» («Закрыть»). Выберите параметр «Save the machine state» («Сохранить состояние машины»), чтобы выйти.

## 2. Работа с домашними каталогами Linux и HDFS

2.1. В терминале от имени пользователя student введите следующую команду:

```
hdfs dfs -ls /
```

Обратите внимание, что существует несколько каталогов. Существует каталог /tmp, где все пользователи могут читать и записывать файлы. Также есть каталог /user. Здесь находятся домашние каталоги пользователей для HDFS. При использовании HDFS у каждого пользователя может быть локальный домашний каталог Linux, а также домашний каталог HDFS. В Linux локальный домашний каталог обычно называется /home/username. Для HDFS домашний каталог находится по адресу /user/username.

2.2. Далее изучите домашние каталоги пользователей в HDFS.

```
hdfs dfs -ls /user
hdfs dfs -ls /user/student
```

2.3. Исследуйте домашние каталоги пользователей для Linux.

```
cd /home
ls -l
cd /home/student
ls -l
cd /home/
```

2.4. Создайте нового пользователя Linux. Создайте домашние каталоги HDFS и Linux для пользователя.

Распространенной задачей администраторов Hadoop является создание новых пользователей. При этом обычно создается домашний каталог пользователя как для Linux, так и для HDFS.

2.4.1. Создайте пользователя Linux и домашний каталог. Для этого вам потребуются привилегии суперпользователя. Префикс команд sudo позволяет нам выполнять привилегированные команды. Мы можем использовать sudo, потому что студент является частью группы wheel, которой была предоставлена эта возможность.

```
sudo useradd student2 -m
```

Установите пароль для нового пользователя. Для простоты мы будем использовать «student2» в качестве пароля. Вы можете получить предупреждение о том, что пароль слишком короткий или что пароль содержит элементы из имени пользователя. Обычно вы хотите быть уверенным, что у вас есть более надежный пароль, однако для нашей лабораторной работы этого пароля будет достаточно.

```
sudo passwd student2
```

Затем добавьте student2 в группу wheel.

Протестируйте новую учетную запись Linux, войдя в систему как student2. Помните, что пароль это «student2». Убедитесь, что домашний каталог Linux создан.

```
su - student2
```

Введите «student2» в качестве пароля.

Затем перейдите в домашний каталог, получите список каталога (пока пустой), выведите на печать текущий рабочий каталог и, наконец, выведите на печать группы, к которым принадлежит student2.

```
cd
ls -l
pwd
groups
```

2.4.2. Создайте домашний каталог HDFS для пользователя student2. Оставьте терминал student2 открытым и откройте другой терминал. Нам нужно будет вводить команды от имени пользователя Hadoop, чтобы внести изменения в HDFS. Обычные пользователи могут вносить изменения только в свой домашний каталог HDFS. Однако им могут быть предоставлены дополнительные привилегии с помощью политик безопасности.

Создадим новый каталог в /user/student2. Далее мы изменим владельца (chown) этого каталога на student2.

```
hdfs dfs -mkdir /user/student2
hdfs dfs -chown student2 /user/student2
```

Теперь вернитесь к терминалу для student2 и убедитесь, что для этого пользователя создан новый домашний каталог HDFS.

```
hdfs dfs -ls /user/student2
```

На самом деле вы не получите никакого списка, так как каталог пуст. Однако, если каталог не существует, вы получите сообщение об ошибке. Попробуйте получить список для /user/student3. Эта команда вернет ошибку «Нет такого файла или каталога».

Сбросьте свою работу, выйдя из всех терминалов. Оставьте один терминал открытым в качестве студента-пользователя для следующих лабораторных работ в следующем разделе.

## 3. Изучение и работа с каталогами HDFS

3.1. Создайте подкаталог в домашнем каталоге студента HDFS и назовите его «MRtest».

```
hdfs dfs -mkdir MRtest
hdfs dfs -ls /user/student
```

3.2. Исследуйте книгу, расположенную в подкаталоге вашего домашнего каталога.

В каталоге /home/student/Data есть копия книги «Приключения Алисы в стране чудес» Льюиса Кэрролла. Перейдите в каталог и изучите файл. ~ (тильда) — это сокращение для пути к вашему домашнему каталогу Linux. В нашем случае это будет /home/student. Итак, cd ~/Data — это сокращение для cd /home/student/Data.

```
cd ~/Data
less alice_in_wonderland.txt
```

Команда less позволяет нам просматривать длинный файл, не прокручивая его слишком далеко. Нажмите Enter, чтобы продолжить прокрутку. Нажмите «q», чтобы выйти и остановить просмотр.

3.3. Поместите файл книги в каталог MRtest.

```
hdfs dfs -put \
  /home/student/Data/alice_in_wonderland.txt \
  /user/student/MRtest/
```

Наша команда «положить» книгу довольно длинная. В Linux мы можем разбивать длинные команды на несколько строк, используя \ в конце строки. Это говорит Linux о том, что команда не закончена и что у нее еще есть продолжение.

Напомним из лекций синтаксис подкоманды put: `hdfs dfs -put source destination`. Источник и место назначения могут быть реальными файлами или каталогами. Итак, в приведенной выше команде мы просим HDFS поместить файл alice_in_wonderland.txt в каталог HDFS /user/student/MRtest.

Убедитесь, что файл был скопирован в место назначения HDFS.

```
hdfs dfs -ls /user/student/MRtest
```

## 4. Исследование HDFS через консоль

В этой работе мы не используем веб-интерфейсы. Вся информация о состоянии HDFS и о том, как хранятся данные, доступна через консольные утилиты и файловую систему Linux.

4.1. Просмотрите общую информацию о файловой системе HDFS.

Команда `hdfs dfsadmin -report` показывает сводку по всей файловой системе: сколько узлов данных зарегистрировано, сколько места занято, сколько свободно, состояние каждого узла.

```
hdfs dfsadmin -report
```

Обратите внимание на раздел `Live datanodes`. В нашей псевдораспределенной среде там будет ровно один узел — `localhost`. В реальном кластере их было бы несколько.

4.2. Изучите состояние конкретного файла.

В HDFS каждый файл разбит на блоки. Информацию о блоках конкретного файла можно получить командой:

```
hdfs fsck /user/student/MRtest/alice_in_wonderland.txt -files -blocks -locations
```

Команда `fsck` (file system check) выведет:

- размер файла,
- количество блоков,
- для каждого блока — его идентификатор (Block ID) и список узлов, на которых он хранится.

Поскольку в нашей среде коэффициент репликации равен 1, каждый блок хранится только на одном узле — `localhost`.

**БОНУС.** Скопируйте значение `Block Pool ID` из вывода команды — оно понадобится в следующем пункте. Формат примерно такой: `BP-1037786283-127.0.0.1-1626250653246`.

4.3. Изучите, где HDFS физически хранит данные на диске.

Данные HDFS лежат не в обычном каталоге, а в специальной структуре внутри `~/hadoopdata`. Найдите каталог с Block Pool ID, который вы скопировали в предыдущем пункте. Для этого войдите как пользователь hadoop и выполните поиск по файловой системе Linux:

```
su - hadoop
sudo find / -name <Block Pool ID> -print
```

Например:

```
sudo find / -name BP-1037786283-127.0.0.1-1626250653246 -print
```

Команда `find` начнет поиск с корневого каталога `/` и рекурсивно пройдет по всем подкаталогам. Вывод будет выглядеть примерно так:

```
/home/hadoop/hadoopdata/hdfs/datanode/current/BP-1234567890-127.0.0.1-1626250653246
find: '/root/Document/My Music': Operation not permitted
find: '/root/Document/My Pictures': Operation not permitted
find: '/root/Document/My Videos': Operation not permitted
```

Не беспокойтесь о трех каталогах, для которых операция не разрешена. Эти каталоги представляют собой смонтированные каталоги, соединяющие папки вашего ПК с системой Linux с помощью VirtualBox.

4.4. Перейдите в найденный каталог и найдите файл с данными.

```
cd <результат find из предыдущего шага>
sudo find . -name "*<Block ID>*" -print
```

Здесь мы снова используем команду find, но на этот раз с точечной нотацией `.` — поиск начинается с текущего каталога. `<Block ID>` — это идентификатор блока, который вы скопировали из вывода `hdfs fsck` (он выглядит как длинное число, например `1234567890`).

Вы должны увидеть два файла с одинаковым Block ID. Один из них имеет расширение `.meta` — это метаданные, бинарный файл, его содержимое вы не сможете прочитать. Второй — это сам блок данных, текстовый файл, в котором Hadoop сохранил содержимое `alice_in_wonderland.txt`.

4.5. Просмотрите содержимое блока данных.

```
less <путь к текстовому файлу>
```

Например:

```
less ./current/finalized/subdir0/subdir0/blk_1073742392
```

Убедитесь, что содержимое совпадает с текстом книги, которую вы загрузили в HDFS.

4.6. Просмотрите метаданные блока.

Рядом с текстовым файлом находится файл метаданных с расширением `.meta`. Его можно посмотреть командой `xxd` или `hexdump` — это бинарный файл, но первые байты содержат версию формата и контрольную сумму.

```
xxd ./current/finalized/subdir0/subdir0/blk_1073742392_1002.meta | head
```

4.7. Изучите историю изменений файловой системы.

HDFS ведет журнал всех операций в файлах `edits` и периодически сохраняет снимок состояния в файл `fsimage`. Оба файла лежат в каталоге NameNode:

```
ls -l ~/hadoopdata/hdfs/namenode/current/
```

Вы увидите файлы:

- `fsimage_*` — снимок состояния файловой системы на момент последнего checkpoint,
- `edits_*` — журнал операций, накопленных после последнего checkpoint,
- `seen_txid` — последний примененный идентификатор транзакции.

Файл `fsimage` — бинарный, но его можно прочитать с помощью утилиты:

```
hdfs oiv -p XML -i ~/hadoopdata/hdfs/namenode/current/fsimage_0000000000000000000 -o /tmp/fsimage.xml
less /tmp/fsimage.xml
```

В этом XML вы увидите список всех файлов и каталогов HDFS на момент снимка.

Журнал `edits` тоже можно преобразовать в текст:

```
hdfs oev -p XML -i ~/hadoopdata/hdfs/namenode/current/edits_0000000000000000001-0000000000000000002 -o /tmp/edits.xml
less /tmp/edits.xml
```

Здесь видны все операции, которые пользователи выполняли с файловой системой: создание файлов, переименование, удаление.

## Работа с YARN/MapReduce

Мы будем использовать файл alice_in_wonderland.txt, который был сохранен в HDFS, для запуска программы MapReduce подсчета слов.

## 1. Включить YARN historyserver

1.1. Откройте новый терминал как hadoop (используйте команду `su - hadoop`) и запустите historyserver.

В Hadoop 3.x команда `mr-jobhistory-daemon.sh` устарела. Используйте:

```
mapred --daemon start historyserver
```

1.2. Убедитесь, что historyserver запущен.

```
jps | grep JobHistoryServer
```

Вы должны увидеть процесс `JobHistoryServer`.

---

## 2. Запустите программу подсчета слов из jar примеров MapReduce

2.1. Откройте новый терминал как student.

2.2. Перейдите в следующий каталог.

```
cd $HADOOP_HOME/share/hadoop/mapreduce
```

2.3. Посмотрите, какие jar-файлы с примерами доступны.

```
ls -l hadoop-mapreduce-examples-*.jar
```

В Hadoop 3.5.0 файл называется `hadoop-mapreduce-examples-3.5.0.jar`. Именно его мы будем использовать. Запомните точное имя.

2.4. Запустите программу подсчета слов.

```
hadoop jar ./hadoop-mapreduce-examples-3.5.0.jar wordcount \
  MRtest WC_Output
```

Программа прочитает все файлы из каталога `MRtest` в вашем домашнем каталоге HDFS, посчитает количество вхождений каждого слова и запишет результат в каталог `WC_Output`.

Во время работы программы вы можете наблюдать за её состоянием через консоль.

2.5. Следите за выполнением задания через консоль.

Откройте ещё один терминал от имени student и посмотрите список всех заданий YARN:

```
yarn application -list
```

Вы увидите таблицу примерно такого вида:

```
Total number of applications (application-types: [], states: [SUBMITTED, ACCEPTED, RUNNING] and tags: []): 1
                Application-Id	    Application-Name	    Application-Type	      User	     Queue	             State	       Final-State	       Progress	                       Start-Time	                 Finish-Time
application_1626987151625_0001	          word count	           MAPREDUCE	    student	   default	           RUNNING	         UNDEFINED	             10%	Fri Jul 23 06:27:36 KST 2021	                          N/A
```

Скопируйте `Application-Id` — он понадобится в следующем пункте. Узнать статус конкретного приложения можно командой:

```
yarn application -status <Application-Id>
```

Например:

```
yarn application -status application_1626987151625_0001
```

Вывод покажет:

- имя приложения (`word count`),
- пользователя (`student`),
- тип (`MAPREDUCE`),
- текущее состояние (`RUNNING`, `FINISHED`, `FAILED`),
- прогресс в процентах,
- время старта и завершения,
- URL для отслеживания (Tracking-URL),
- диагностические сообщения, если задание упало.

Дождитесь, пока задание перейдёт в состояние `FINISHED`. Проверить можно так:

```
yarn application -list -appStates ALL
```

2.6. Посмотрите логи задания.

После завершения задания все его логи доступны через команду:

```
yarn logs -applicationId <Application-Id>
```

Например:

```
yarn logs -applicationId application_1626987151625_0001
```

Вывод будет содержать stdout и stderr всех контейнеров, которые выполняли задание: ApplicationMaster, Map-задачи, Reduce-задачи. Это очень полезно при отладке.

2.7. Изучите отчёт о выполненном задании.

После завершения задания можно получить сводный отчёт:

```
mapred job -history WC_Output
```

Здесь `WC_Output` — имя выходного каталога в HDFS. Команда выведет статистику: сколько Map-задач было запущено, сколько Reduce, сколько времени заняла каждая фаза, среднее время выполнения, и т. д.

2.8. Просмотрите результат работы программы.

```
hdfs dfs -ls /user/student/WC_Output
hdfs dfs -cat /user/student/WC_Output/part-r-00000 | head -20
```

Первая команда покажет содержимое выходного каталога — там будет несколько файлов:

- `_SUCCESS` — маркер успешного завершения задания,
- `part-r-00000` — сам результат подсчёта слов.

Вторая команда выведет первые 20 строк результата — пары «слово — количество вхождений», отсортированные по алфавиту.

2.9. Подсчитайте общее число уникальных слов в файле.

```
hdfs dfs -cat /user/student/WC_Output/part-r-00000 | wc -l
```

2.10. Посмотрите, сколько раз встречается конкретное слово. Например, «Alice».

```
hdfs dfs -cat /user/student/WC_Output/part-r-00000 | grep -iw Alice
```

Вы можете перезапустить задание. Если это нужно сделать, вам придется удалить выходной каталог. Параметр `-r` команды `rm` (удалить) указывает Hadoop также рекурсивно удалить все подпапки.

```
hdfs dfs -rm -r WC_Output
```

## 3. Диагностика через консоль

В этой лабораторной работе вся диагностика ведётся через консольные утилиты. Ниже — несколько полезных команд, которые пригодятся вам при работе с Hadoop.

3.1. Список всех запущенных приложений YARN:

```
yarn application -list
```

3.2. Список всех приложений, включая завершённые:

```
yarn application -list -appStates ALL
```

3.3. Информация о конкретном приложении:

```
yarn application -status <Application-Id>
```

3.4. Логи конкретного приложения:

```
yarn logs -applicationId <Application-Id>
```

3.5. Список узлов кластера YARN:

```
yarn node -list
```

В псевдораспределённой среде вы увидите один узел — `localhost`.

3.6. Проверка состояния HDFS:

```
hdfs dfsadmin -report
```

3.7. Проверка конкретного файла в HDFS:

```
hdfs fsck /путь/к/файлу -files -blocks -locations
```

3.8. Просмотр логов Hadoop напрямую в файловой системе Linux:

```
ls -l ~/hadoop/logs/
tail -100 ~/hadoop/logs/hadoop-hadoop-namenode-localhost.localdomain.log
```

Здесь `~` — это домашний каталог пользователя hadoop, то есть `/home/hadoop`. Логи каждого демона лежат в отдельном файле — NameNode, DataNode, ResourceManager, NodeManager. При возникновении проблем всегда начинайте диагностику с этих логов.

---

## 4. Остановка служб

По окончании работы остановите службы HDFS и YARN — это корректно завершит все демоны и сохранит состояние файловой системы.

4.1. Войдите как пользователь hadoop.

```
su - hadoop
```

4.2. Остановите YARN.

```
cd ~/hadoop/sbin
./stop-yarn.sh
```

4.3. Остановите HDFS.

```
./stop-dfs.sh
```

4.4. Убедитесь, что все демоны остановлены.

```
jps
```

В выводе не должно остаться ни `NameNode`, ни `DataNode`, ни `SecondaryNameNode`, ни `ResourceManager`, ни `NodeManager`. Если какие-то процессы ещё живы, подождите несколько секунд и повторите проверку.
